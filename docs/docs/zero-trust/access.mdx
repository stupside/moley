Add an `access:` block to any app to protect it with Cloudflare Access. Moley creates the Access Application automatically and tears it down on stop.

## Basic Example

```yaml title="moley.yml"
ingress:
  zone: "yourdomain.com"
  mode: subdomain
  apps:
    - target:
        port: 3000
        hostname: "localhost"
        protocol: http
      expose:
        subdomain: "app"
      access:
        providers:
          - github
        session_duration: "24h"
```

## Origin Validation

For every app with an `access:` block, Moley also configures cloudflared to require a valid Access token on each request (`originRequest.access`). Requests that did not pass through Cloudflare Access, for example if the Access Application is deleted while the tunnel runs, are rejected before they reach your app.

Tunnels started with an older Moley version get this check after a `moley tunnel stop` and a fresh start; until then, Moley logs a warning. The check needs the token to have Access: Organizations Read.

## Identity Providers

The `providers` list accepts Cloudflare IdP type names (e.g. `github`, `google-workspace`). Moley matches these against the IdPs configured in your account and resolves them to UUIDs. See [Cloudflare identity provider integration](https://developers.cloudflare.com/cloudflare-one/identity/idp-integration/) for available types and setup.

## Cloudflare API Passthrough

All fields under `access:` (other than `providers`) are forwarded to the Cloudflare Access API as-is. See the [Cloudflare self-hosted app configuration](https://developers.cloudflare.com/cloudflare-one/applications/configure-apps/self-hosted-apps/) for all available fields.

## Attaching Policies

Reference named policies from [access.policies](/docs/policies/) by name:

```yaml
ingress:
  apps:
    - expose:
        subdomain: "app"
      access:
        providers:
          - github
      policies:
        - team-only    # references access.policies[name=team-only]
```
